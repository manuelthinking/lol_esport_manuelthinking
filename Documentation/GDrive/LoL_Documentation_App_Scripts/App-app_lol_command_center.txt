# App-app_lol_command_center

## Purpose
Streamlit Command Center for the LoL DFS workflow.

In plain English:
This is the main control dashboard for checking slate health, starters, Bayes/lane-power status, ownership data, contest results, top 1% lineups, and running registered pipeline jobs from the Action Engine.

This app is meant to be the central "iRebal-style" operational screen for the LoL project.

## Type
Streamlit app.

## Suggested Run Command
cd C:\DailyDFS\LoL
python -m streamlit run .\app_lol_command_center.py

## Data It Creates
This app does not directly create core DFS data tables.

However, through the Daily Commands / Action Engine page, it can trigger jobs that create or update data.

The app itself mainly displays:
- current slate status
- data health
- exceptions
- starter review
- Bayes review
- ownership review
- contest review
- top 1% lineup review
- job run results

## Page Details

### Slate Dashboard
Shows high-level slate status:
- overall status
- DK slate loaded/missing
- manual starters ready/needs review
- contest results loaded/not loaded
- slate rows
- team count
- player rows
- TEAM rows
- lineup file count
- manual starter rows
- marked starters
- lane rating rows
- ownership rows
- raw contest rows

Also displays the selected slate player table.

### Data Health
Shows pass/fail style checks for:
- DK slate loaded
- manual starters file exists
- manual starters selected
- lane power signal available
- ownership training available
- Bayes matched rows
- Bayes missing rows
- contest standings loaded
- raw player ownership loaded
- generated lineup files

Also shows file counts for:
- slate CSV files
- contest ZIP files
- lineup CSV files

### Exceptions
Builds a review table of operational issues.

Examples:
- no DK slate rows loaded
- no player rows
- no TEAM rows
- manual_starters.csv missing
- no starters selected
- low starter count
- no lane rating rows
- ownership missing
- Bayes values missing
- low Bayes sample
- ownership includes non-starters
- no generated lineup files
- no raw contest standings
- no raw ownership loaded

The page includes a suggested fix order:
1. Fix missing slate or starter issues.
2. Fix Bayes matching issues.
3. Review ownership gaps.
4. Build lineups.
5. Load contest results after lock/contest completion.

### Starter Review
Reads manual_starters.csv and displays:
- manual rows
- marked starters
- teams
- filterable starter table
- selected slate players

### Bayes Review
Uses vw_lol_ownership_training and vw_lol_bayes_prediction_backtest_match_level.

Displays:
- Bayes matched/missing count
- average Bayes win %
- Bayes by team
- player-level Bayes / ownership table
- recent Bayes backtest
- winner accuracy
- score accuracy

### Ownership Review
Displays:
- ownership rows
- average ownership
- max ownership
- player count
- ownership by team
- player ownership detail

### Contest Review
Uses lol.vw_contest_summary and lol.vw_finish_bucket_summary.

Displays:
- contests
- lineups
- best rank
- winning score
- contest summary
- finish bucket summary

### Top 1% Lineups
Uses lol.vw_top_1pct_lineups.

Displays:
- top 1% lineup rows
- best score
- average ownership
- average salary left
- captain position summary
- top lineup detail

### Daily Commands
Uses engine.jobs as an Action Engine.

Displays:
- registered jobs
- job group
- job type
- target
- timeout
- description

Can run one selected job and displays:
- success/failure
- return code
- duration
- command
- stdout
- stderr

Also contains manual command reference blocks for:
- daily slate prep
- open lineup builder
- post-contest review

## Does This Need To Be Run Daily?
Yes, this should be opened daily on slate days.

It is not a data builder by itself, but it is the daily control panel for:
- checking data health
- running jobs
- reviewing outputs
- deciding whether the slate is ready to build
- reviewing post-contest results

## When To Use
Use this app:
- after loading a DK slate
- after generating manual starters
- before building lineups
- after running Bayes/lane-power refreshes
- after building lineups
- after contest results are loaded
- whenever you need to diagnose missing data

## Suggested Workflow Placement
Pre-lock:
DK slate ingest
    -> Command Center Data Health
    -> Starter Review
    -> Exceptions
    -> Bayes Review / Lane Power
    -> Lineup Builder

Post-contest:
contest standings ingest
    -> transform lineups
    -> enrich lineups
    -> Command Center Contest Review / Top 1% Lineups

## Important Risk Areas

### Risk 1: Many SQL view dependencies
If any SQL view is missing or broken, the related page may show SQL errors.

### Risk 2: Caching
Uses Streamlit cache. If data is stale, use Refresh Data / Clear Cache.

### Risk 3: Action Engine dependency
Daily Commands depends on engine.jobs. If jobs are not registered there, the page will not be useful for running tasks.

### Risk 4: Status logic is only as good as row counts
The health/status checks are helpful but not a guarantee that every underlying row is correct.

### Risk 5: File matching for lineup count
Lineup file count is based on filename patterns in the lineups folder. Bad naming can make the app think lineups are missing.
