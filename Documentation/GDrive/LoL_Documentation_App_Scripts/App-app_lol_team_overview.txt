# App-app_lol_team_overview

## Purpose
Streamlit slate team overview and projection research app.

In plain English:
This app reviews the selected LoL slate from a team, series-profile, Bayes, lane-power, and player-projection perspective. It helps decide which teams to stack, which match scenarios to use, and which players project best before building lineups.

This is one of the main pre-lock analysis apps.

## Type
Streamlit app.

## Suggested Run Command
cd C:\DailyDFS\LoL
python -m streamlit run .\app_lol_team_overview.py

Also includes Lane Power PIT Adjustment:

- average DK with bonus

- deaths

- sweep score

### Slate Predictions

Outputs:

### Player Table

### Matchups

### Raw Data

## Manual Starters
The app can use manual starters only.

If enabled:
- reads manual_starters.csv
- keeps only rows where is_starter = 1 and player/team/position match

If missing or unmatched:
- app shows all non-CPT DK rows with a warning/info message

## Key Internal Logic

### Team Overview
Aggregates player rows by team and game_info.

### Slate Predictions
Uses:
- team rating
- total average DK
- kill edge
- DK edge
- value
- historical series DFS score

### Bayes Strength Read
Compares current team/lane strength buckets against historical matchup buckets.

Uses smoothing toward league priors when samples are small.

### Suggested Scenarios
Chooses:
- favorite team
- underdog team
- winner result
- loser result
- confidence
- action note for lineup builder

The model is designed to default toward 2-1 when sweep confidence is not strong enough.

## What Uses This App
This app feeds manual decision-making for:
- app_lol_lineup_builder.py
- scenario selection
- team stack selection
- player pool decisions
- CPT decisions
- TEAM slot decisions

It does not directly write output, but it strongly informs lineup-building choices.

## Run Frequency
Run on slate days after:
1. DK slate has been loaded.
2. manual_starters.csv is prepared.
3. historical profile and Bayes/lane views are current enough.

## Suggested Workflow Placement
DK slate ingest
    -> build_manual_starters_from_dk
    -> app_lol_team_overview
    -> review Bayes / lane power / suggested scenarios
    -> app_lol_lineup_builder
    -> lineup CSVs

## Important Risk Areas

### Risk 1: Many SQL dependencies
This app depends on many views/tables. If one breaks, a tab may be empty or show warnings.

### Risk 2: Hard-coded season filters
Some SQL queries filter season = 2026. This needs review when moving into a new season.

### Risk 3: Team name matching
Series profiles use full team names, while slates may use abbreviations. Team-name mapping issues can cause missing profiles or Bayes reads.

### Risk 4: Manual starter fallback
If starters do not match, the app may show all non-CPT rows.

### Risk 5: Projection logic is first-pass
The projections are helpful for decision-making, but the lineup builder’s scenario model may differ slightly.

### Risk 6: Lane Power PIT signals depend on live view
If vw_lol_slate_lane_power_signal_live_v1 is missing current slate rows, lane-power section will be empty.

## Recommended Future Enhancements
- Add season parameter instead of hard-coded 2026.
- Add direct "send scenario to lineup builder" workflow.
- Add slate-specific starter validation.
- Add clearer team-name mapping diagnostic.
- Add export of suggested scenario notes.
- Add side-by-side Bayes vs Lane Power vs Team Series profile summary.
- Add warning if historical data freshness is old.
