# SQL-11_create_lol_bayes_prediction_tracking

## Source SQL File
11_create_lol_bayes_prediction_tracking.sql

## Purpose
Creates a table for saving Bayesian model predictions before results are known.

In plain English:
This table is meant to store the model's pre-result prediction for each slate matchup so you can evaluate it later against actual results.

This is important because it prevents backfitting. You save the prediction before games happen, then later compare it to what actually happened.

## SQL Object Created
Creates:

dbo.lol_bayes_prediction_tracking

This is a physical table.

## Data It Consumes
This SQL file does not consume data directly.

It only creates:
- table
- unique index
- lookup index
- accuracy review index

A separate process is needed to insert predictions before lock and update actual results after completion.

## Health Checks

Check table exists:
SELECT
    OBJECT_ID('dbo.lol_bayes_prediction_tracking', 'U') AS object_id;

Check row count:
SELECT
    COUNT(*) AS prediction_rows
FROM dbo.lol_bayes_prediction_tracking;

Check predictions by slate:
SELECT
    slate_date,
    slate_name,
    prediction_source,
    COUNT(*) AS prediction_rows,
    COUNT(DISTINCT game_info) AS matchups,
    MIN(created_at) AS first_created_at,
    MAX(created_at) AS last_created_at
FROM dbo.lol_bayes_prediction_tracking
GROUP BY slate_date, slate_name, prediction_source
ORDER BY slate_date DESC, slate_name;

Check unlocked/backfilled risk:
SELECT TOP 100
    slate_date,
    slate_name,
    game_info,
    teamname,
    opponent_teamname,
    prediction_source,
    locked_before_results,
    created_at,
    actual_series_result,
    winner_correct,
    score_correct,
    path_correct
FROM dbo.lol_bayes_prediction_tracking
ORDER BY slate_date DESC, game_info, teamname;

Check accuracy:
SELECT
    prediction_source,
    sample_type,
    COUNT(*) AS evaluated_rows,
    AVG(CAST(winner_correct AS FLOAT)) AS winner_accuracy,
    AVG(CAST(score_correct AS FLOAT)) AS score_accuracy,
    AVG(CAST(path_correct AS FLOAT)) AS path_accuracy
FROM dbo.lol_bayes_prediction_tracking
WHERE winner_correct IS NOT NULL
GROUP BY prediction_source, sample_type
ORDER BY evaluated_rows DESC;

## Important Risk Areas

### Risk 1: Table creation only
This file does not save predictions or update results. Those processes still need to be built.

### Risk 2: Must be populated before results
The value of this table depends on predictions being saved before the matches happen.

### Risk 3: Unique index uses teamname/opponent_teamname
If team naming changes, duplicate prevention may not behave as intended.

### Risk 4: game_info can be nullable in unique index
SQL Server unique indexes allow multiple NULL values in some contexts depending on column combinations. If game_info/teamname values are null, duplicate protection may be weaker than expected.

### Risk 5: Actual result update process missing
Without a post-results updater, accuracy fields remain null.
