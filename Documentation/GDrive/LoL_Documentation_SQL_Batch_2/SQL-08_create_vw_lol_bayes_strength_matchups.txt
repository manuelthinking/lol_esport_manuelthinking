# SQL-08_create_vw_lol_bayes_strength_matchups

## Source SQL File
08_create_vw_lol_bayes_strength_matchups.sql

## Purpose
Creates the combined Bayesian strength matchup view.

In plain English:
This view joins team-strength matchup buckets with lane-strength matchup buckets so the model can evaluate historical examples that match both overall team strength and lane strength.

This is one of the core views used by the Streamlit Bayesian Matchup Read.

## SQL Object Created
Creates:

dbo.vw_lol_bayes_strength_matchups

This is a view.

## Data It Creates
Creates a view with one row per:

team per historical series

## Grain
one row per team per historical series

Key identifiers:
- series_id
- teamname
- opponent_teamname

## Main Logic
The view selects team-strength fields from dbo.vw_lol_team_strength_matchups and lane-strength fields from dbo.vw_lol_lane_strength_matchups.

It joins on:
- series_id
- league
- season
- normalized teamname
- normalized opponent_teamname

## Health Checks

Check row count:
SELECT
    COUNT(*) AS rows_count
FROM dbo.vw_lol_bayes_strength_matchups;

Check sample counts by strength/lane bucket:
SELECT
    league,
    season,
    strength_matchup_bucket,
    mid_lane_matchup_bucket,
    bot_lane_matchup_bucket,
    sup_lane_matchup_bucket,
    COUNT(*) AS sample_rows,
    AVG(CAST(won_series AS FLOAT)) AS win_rate
FROM dbo.vw_lol_bayes_strength_matchups
GROUP BY
    league,
    season,
    strength_matchup_bucket,
    mid_lane_matchup_bucket,
    bot_lane_matchup_bucket,
    sup_lane_matchup_bucket
ORDER BY sample_rows DESC;

Check missing lane layer:
SELECT TOP 100
    league,
    season,
    series_date,
    teamname,
    opponent_teamname,
    strength_matchup_bucket,
    mid_lane_matchup_bucket,
    bot_lane_matchup_bucket,
    sup_lane_matchup_bucket
FROM dbo.vw_lol_bayes_strength_matchups
WHERE mid_lane_matchup_bucket IS NULL
   OR bot_lane_matchup_bucket IS NULL
   OR sup_lane_matchup_bucket IS NULL
ORDER BY series_date DESC;

## Important Risk Areas

### Risk 1: Inherits hard-coded 2026 from upstream views
The direct SQL file does not hard-code 2026, but both upstream views likely do. This view inherits that season limitation.

### Risk 2: Left join to lane strength
If the lane-strength matchup view does not match, team-strength rows still appear but lane columns can be NULL.

### Risk 3: Team/opponent name matching
The join depends on normalized teamname and opponent_teamname. Mismatches can lose lane fields.

### Risk 4: Potential point-in-time leakage
This view uses season-level strength buckets from completed data. For true historical backtesting, a point-in-time version may be needed.

### Risk 5: Sample fragmentation
Combining team strength with MID/BOT/SUP lane buckets can create very small samples. The Streamlit app handles this by falling back to broader samples, but sample counts need monitoring.

## Recommended Future Enhancements
- Create a point-in-time version for backtesting.
- Add season/date filtering strategy.
- Add unknown/null lane bucket fallback in the final view if desired.
- Add sample count summary view.
- Add Command Center health checks for sample fragmentation.
- Consider current-season and recent-form variants.
