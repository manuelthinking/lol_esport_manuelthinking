# SQL-06_create_vw_lol_lane_strength_bucket

## Source SQL File
06_create_vw_lol_lane_strength_bucket.sql

## Purpose
Creates a view that labels each team's lane/position as strong, neutral, or weak.

In plain English:
This view compares each team’s average DK points by lane against the league-position average. It then assigns each lane a strength bucket.

This is used for lane-power and Bayesian matchup logic.

## SQL Object Created
Creates:

dbo.vw_lol_lane_strength_bucket

This is a view.

## Data It Consumes

### Source Table
- dbo.fact_lol_player_game

## Data It Creates
Creates a view with one row per:

- league
- season
- teamname
- position

## Grain
league + season + teamname + position

## Main Filters
The view only includes:

- league IN ('LPL', 'LCK')
- season = 2026
- team_name IS NOT NULL
- player_name IS NOT NULL
- position in top/jng/jungle/mid/bot/adc/sup/support

Important:
This view is hard-coded to 2026.

## Position Normalization
The view normalizes position values:

- bot / adc -> BOT
- jng / jungle -> JNG
- mid -> MID
- top -> TOP
- sup / support -> SUP

## Bucket Logic

### lane_strength_bucket
- lane_games < 5 -> neutral
- lane_dk_index >= 1.10 -> strong
- lane_dk_index <= 0.90 -> weak
- everything else -> neutral

### lane_strength_sample_label
- lane_games < 5 -> low_sample
- lane_games between 5 and 14 -> medium_sample
- else -> solid_sample

## Health Checks

Check row count:
SELECT
    COUNT(*) AS rows_count
FROM dbo.vw_lol_lane_strength_bucket;

Check lane bucket distribution:
SELECT
    league,
    season,
    position,
    lane_strength_bucket,
    lane_strength_sample_label,
    COUNT(*) AS team_lanes
FROM dbo.vw_lol_lane_strength_bucket
GROUP BY league, season, position, lane_strength_bucket, lane_strength_sample_label
ORDER BY league, position, lane_strength_bucket;

Check strongest lanes:
SELECT TOP 100
    league,
    season,
    teamname,
    position,
    lane_games,
    lane_players,
    lane_avg_dk,
    league_position_avg_dk,
    lane_dk_index,
    lane_strength_bucket,
    lane_strength_sample_label
FROM dbo.vw_lol_lane_strength_bucket
ORDER BY lane_dk_index DESC;

Check missing/low samples:
SELECT
    league,
    season,
    teamname,
    position,
    lane_games,
    lane_strength_bucket,
    lane_strength_sample_label
FROM dbo.vw_lol_lane_strength_bucket
WHERE lane_games < 5
ORDER BY league, teamname, position;

## Important Risk Areas

### Risk 1: Hard-coded season = 2026
This view will need updating for future seasons or multi-season analysis.

### Risk 2: Depends on fact_lol_player_game
If player game data is stale or uses placeholder DK scoring, lane buckets may be misleading.

### Risk 3: DK points drive lane strength
This is intentional for DFS, but it may differ from pure real-life lane strength.

### Risk 4: Small sample lanes forced neutral
This avoids overreacting but can hide strong new roster changes.

### Risk 5: Team name consistency
Downstream joins depend on teamname matching other views and slate mapping.

## Recommended Future Enhancements
- Add season parameter or create current-season view.
- Add point-in-time version to avoid future leakage in backtests.
- Add weighted recent form version.
- Consider combining DK index with gold/xp/cs/dpm indexes.
- Add separate carry-lane strength rollup for MID/BOT/SUP.
- Add date freshness checks.
