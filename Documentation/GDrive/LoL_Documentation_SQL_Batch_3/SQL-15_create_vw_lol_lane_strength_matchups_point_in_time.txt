# SQL-15_create_vw_lol_lane_strength_matchups_point_in_time

## Source SQL File
15_create_vw_lol_lane_strength_matchups_point_in_time.sql

## Purpose
Creates point-in-time lane strength matchup buckets.

In plain English:
For each historical target series, this view compares each team's point-in-time lane strength against the opponent's point-in-time lane strength. It then pivots those comparisons into one row per team/series with TOP/JNG/MID/BOT/SUP matchup buckets.

This view avoids future-data leakage because its source lane strengths are calculated only from games before the target series.

- teamname

## Main Logic

### base CTE
Reads point-in-time lane bucket rows.

### with_opponent CTE
Self-joins each team lane row to the opponent's lane row for the same target series and position.

Join conditions:
- same target_series_id
- same league
- same season
- same position
- team opponent matches opponent teamname
- team teamname matches opponent opponent_teamname

### pivoted CTE
Pivots one row per position into one row per team/series.

Creates:
- team lane strength by role
- opponent lane strength by role
- lane matchup bucket by role
- sample labels
- DK indexes
- games counts
- kill/assist indexes

### Final SELECT
Fills missing lane strength values as unknown and creates:
- top_lane_matchup_bucket
- jng_lane_matchup_bucket
- mid_lane_matchup_bucket
- bot_lane_matchup_bucket
- sup_lane_matchup_bucket

## Health Checks

Check row count:
SELECT
    COUNT(*) AS rows_count
FROM dbo.vw_lol_lane_strength_matchups_point_in_time;

Check lane matchup bucket distribution:
SELECT
    league,
    season,
    mid_lane_matchup_bucket,
    bot_lane_matchup_bucket,
    sup_lane_matchup_bucket,
    COUNT(*) AS rows_count,
    AVG(CAST(actual_won_series AS FLOAT)) AS actual_win_rate
FROM dbo.vw_lol_lane_strength_matchups_point_in_time
GROUP BY
    league,
    season,
    mid_lane_matchup_bucket,
    bot_lane_matchup_bucket,
    sup_lane_matchup_bucket
ORDER BY rows_count DESC;

Check unknown lane matchup rows:
SELECT TOP 100
    league,
    season,
    target_series_date,
    teamname,
    opponent_teamname,
    top_lane_matchup_bucket,
    jng_lane_matchup_bucket,
    mid_lane_matchup_bucket,
    bot_lane_matchup_bucket,
    sup_lane_matchup_bucket
FROM dbo.vw_lol_lane_strength_matchups_point_in_time
WHERE top_lane_matchup_bucket LIKE 'unknown%'
   OR jng_lane_matchup_bucket LIKE 'unknown%'
   OR mid_lane_matchup_bucket LIKE 'unknown%'
   OR bot_lane_matchup_bucket LIKE 'unknown%'
   OR sup_lane_matchup_bucket LIKE 'unknown%'
ORDER BY target_series_date DESC;

Check expected two rows per series:
SELECT
    target_series_id,
    COUNT(*) AS rows_count,
    COUNT(DISTINCT teamname) AS teams
FROM dbo.vw_lol_lane_strength_matchups_point_in_time
GROUP BY target_series_id
HAVING COUNT(*) <> 2
ORDER BY rows_count;

## Important Risk Areas

### Risk 1: Inherits hard-coded 2026
This view inherits the season limitation from view 14.

### Risk 2: Self-join by team/opponent/position
If opponent team names do not match cleanly, opponent lane fields become unknown.

### Risk 3: Missing lane rows can become unknown buckets
This prevents null crashes but may mask data quality problems.

### Risk 4: One row per team perspective
Each target series should have two rows. Downstream logic should not treat the rows as unique matchups unless it expects team perspective rows.

### Risk 5: Carry-lane emphasis is not built in
The view exposes all lanes, but downstream logic decides whether MID/BOT/SUP matter more.

## Recommended Future Enhancements
- Add unknown-rate Command Center health check.
- Add carry_lane_matchup_summary field.
- Add current-slate version for pre-lock use.
- Remove/parameterize hard-coded season in upstream view.
- Add validation for two rows per target_series_id.
