# SQL-17_create_lol_bayes_prediction_backtest

## Source SQL File
17_create_lol_bayes_prediction_backtest.sql

## Purpose
Creates the physical table used to store historical Bayesian prediction backtest rows.

In plain English:
This table stores what the Bayes model would have predicted for each historical team-side series row using point-in-time data. It is designed to let you evaluate whether the Bayes model predicted the winner, score type, and exact team path correctly.

This is part of the historical model-validation layer.

## SQL Object Created
Creates:

dbo.lol_bayes_prediction_backtest

This is a physical table.

Check table exists:
SELECT
    OBJECT_ID('dbo.lol_bayes_prediction_backtest', 'U') AS object_id;

SELECT
    COUNT(*) AS rows_count
FROM dbo.lol_bayes_prediction_backtest;

Check rows by league/season/source:
SELECT
    league,
    season,
    prediction_source,
    prior_weight,
    COUNT(*) AS rows_count,
    COUNT(DISTINCT target_series_id) AS series_count,
    MIN(target_series_date) AS first_date,
    MAX(target_series_date) AS last_date
FROM dbo.lol_bayes_prediction_backtest
GROUP BY league, season, prediction_source, prior_weight
ORDER BY season DESC, league, prediction_source;

Check duplicate team-side rows:
SELECT
    target_series_id,
    teamname,
    opponent_teamname,
    prediction_source,
    prior_weight,
    COUNT(*) AS rows_count
FROM dbo.lol_bayes_prediction_backtest
GROUP BY
    target_series_id,
    teamname,
    opponent_teamname,
    prediction_source,
    prior_weight
HAVING COUNT(*) > 1;

## Important Risk Areas

### Risk 1: Table creation only
This file does not populate the table.

### Risk 2: Schema must match population script
If 18_populate_lol_bayes_prediction_backtest.sql outputs fields not present here, the MERGE will fail. This batch appears aligned, but keep them together.

### Risk 3: Team-side grain can be misunderstood
This table is not one row per match. It is one row per team-side prediction. Use the match-level view for match-level summaries.

### Risk 4: Prior weight included in unique key
This allows multiple backtests with different prior weights. That is useful, but downstream queries should filter prior_weight or group by it.

### Risk 5: Existing table is not dropped
If the table already exists with an older schema, this file will not alter it. It only creates the table if missing.
