## Purpose
Creates the base player lane-power view.

In plain English:
This view aggregates historical player-game data by player/team/lane and produces average lane-power metrics such as DK points, kills, deaths, assists, DPM, damage share, gold/xp/cs diff at 10, vision, first blood rate, and KDA proxy.

This is a base feature view for lane-power modeling.

## SQL Object Created
Creates or alters:

dbo.vw_lol_player_lane_power_base_v1

This is a view.

## Data It Consumes

### Source Table
- dbo.fact_lol_player_game

## Data It Creates
Creates one row per:

league + lane + team + player

## Grain
One row per player/team/lane aggregation.

## Main Filters
The base CTE filters to:

- league IN ('LPL', 'LCK')
- season = 2026
- position IS NOT NULL
- player_name IS NOT NULL
- team_name IS NOT NULL

The final output filters to:
- games_played >= 3

Important:
This view is hard-coded to season = 2026.

## Position / Lane Normalization
The view normalizes position into lane:

- bot / adc -> ADC
- jng / jun / jungle -> JNG
- everything else -> UPPER(position)

Expected lanes:
- TOP
- JNG
- MID
- ADC
- SUP

## KDA Proxy Logic
If deaths = 0:
- kda_proxy = kills + assists

Else:
- kda_proxy = (kills + assists) / deaths

This is averaged across player games.

## Health Checks

Check row count:
SELECT
    COUNT(*) AS rows_count
FROM dbo.vw_lol_player_lane_power_base_v1;

Check rows by lane:
SELECT
    league,
    lane,
    COUNT(*) AS player_lane_rows,
    AVG(games_played) AS avg_games_played,
    AVG(avg_dk_points) AS avg_dk_points
FROM dbo.vw_lol_player_lane_power_base_v1
GROUP BY league, lane
ORDER BY league, lane;

Check strongest player lane rows:
SELECT TOP 100
    league,
    lane,
    team,
    player_name,
    games_played,
    win_rate,
    avg_dk_points,
    kills_per_game,
    assists_per_game,
    dpm,
    avg_damage_share,
    avg_gold_diff_10,
    kda_proxy
FROM dbo.vw_lol_player_lane_power_base_v1
ORDER BY avg_dk_points DESC;

Check low sample exclusion:
SELECT
    COUNT(*) AS all_player_lane_candidates
FROM
(
    SELECT
        league,
        CASE 
            WHEN LOWER(position) IN ('bot', 'adc') THEN 'ADC'
            WHEN LOWER(position) IN ('jng', 'jun', 'jungle') THEN 'JNG'
            ELSE UPPER(position)
        END AS lane,
        team_name,
        player_name,
        COUNT(*) AS games_played
    FROM dbo.fact_lol_player_game
    WHERE league IN ('LPL', 'LCK')
      AND season = 2026
      AND position IS NOT NULL
      AND player_name IS NOT NULL
      AND team_name IS NOT NULL
    GROUP BY
        league,
        CASE 
            WHEN LOWER(position) IN ('bot', 'adc') THEN 'ADC'
            WHEN LOWER(position) IN ('jng', 'jun', 'jungle') THEN 'JNG'
            ELSE UPPER(position)
        END,
        team_name,
        player_name
) x
WHERE games_played < 3;

## Important Risk Areas

### Risk 1: Duplicate file numbering
This file is numbered 20 but another ownership-training file is also numbered 20. Rename this one to 21.

### Risk 2: Hard-coded season = 2026
This will need updating for future seasons.

### Risk 3: Depends on fact_lol_player_game dk_points
If fact_lol_player_game uses placeholder DK scoring, avg_dk_points will inherit that limitation.

### Risk 4: opponent_name may be null
The base select includes opponent_name from fact_lol_player_game. Earlier script documentation noted opponent_name may be null in build_player_games.py. This view does not output opponent, but source quality still matters.

### Risk 5: Player/team aggregation can split roster changes
Because grain includes team, the same player on different teams will have separate rows. That is usually good for current team context.

### Risk 6: Minimum 3 games filter
This removes very thin samples but can hide new players/subs.
