# Script-build_player_games

## Purpose
Builds the player-level game fact table from Oracle Elixir staging rows.

In plain English:
It reads JSON rows from raw.oracle_elixir_match_data_staging, keeps only player rows, converts them into structured columns, calculates basic DK points, and writes them to dbo.fact_lol_player_game.

This is a core upstream script for historical player, lane, and matchup analysis.

## Data It Consumes

### Source Table
- raw.oracle_elixir_match_data_staging

The script reads:
- row_json

Each row_json contains one Oracle Elixir row.

## Rows It Keeps
Only player positions are kept:
- top
- jng
- mid
- bot
- sup

Team rows and non-player rows are ignored.

## DK Points Logic
The current script uses a simple placeholder DK scoring formula:

dk_points = kills * 3 + assists * 2 - deaths

Important:
This is not full DraftKings LoL scoring yet.

It does not currently include:
- creep score points
- 10+ kills/assists bonus
- games-not-played bonus
- other DK-specific scoring components

This table is useful for early modeling, but full DK scoring is handled more completely in later team-game / series scripts.

## Refresh Behavior
The script runs:

TRUNCATE TABLE dbo.fact_lol_player_game

Then inserts all rebuilt rows from staging.

This is a full rebuild table.

## SQL Health Checks

Check row counts:
SELECT
    season,
    league,
    COUNT(*) AS player_game_rows,
    COUNT(DISTINCT game_id) AS unique_games,
    MIN(game_date) AS first_game_date,
    MAX(game_date) AS last_game_date
FROM dbo.fact_lol_player_game
GROUP BY season, league
ORDER BY season DESC, league;

Check 10 player rows per game:
SELECT
    game_id,
    COUNT(*) AS player_rows,
    COUNT(DISTINCT team_name) AS teams,
    COUNT(DISTINCT position) AS positions
FROM dbo.fact_lol_player_game
GROUP BY game_id
HAVING COUNT(*) <> 10
ORDER BY game_id;

Check latest rows:
SELECT TOP 50
    game_date,
    league,
    game_id,
    side,
    team_name,
    position,
    player_name,
    champion,
    kills,
    deaths,
    assists,
    dk_points
FROM dbo.fact_lol_player_game
ORDER BY game_date DESC, game_id, side, position;

## Important Risk Areas

### Risk 1: Full truncate and rebuild
If the insert fails after truncate, dbo.fact_lol_player_game can be empty until rerun.

### Risk 2: DK scoring is only a placeholder
The current dk_points formula does not represent full DK scoring. Be careful using it as final fantasy scoring.

### Risk 3: Depends on staging JSON column names
If Oracle columns change or staging JSON keys are different, fields may become null.

### Risk 4: opponent_name is always None
The script currently sets opponent_name to None. If downstream logic needs opponent_name, it must be derived elsewhere or added later.

### Risk 5: Limited fields
This script captures 10-minute diff fields but does not currently include 15-minute diff fields. Other scripts may use a richer Oracle CSV path for 15-minute metrics.

## Recommended Future Enhancements
- Upgrade dk_points to full DraftKings LoL scoring.
- Populate opponent_name by game/team pairing.
- Add 15-minute metrics if available in staging.
- Add validation for exactly 10 player rows per game.
- Add source_year/source_file or loaded_at lineage fields if not already handled by target table.
