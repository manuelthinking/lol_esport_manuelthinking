# Script-build_lane_matchups

## Purpose
Builds lane matchup records by pairing blue-side and red-side players from the same game and position.

In plain English:
It takes player-game rows from dbo.fact_lol_player_game and creates one lane matchup row per game/position.

For each game, it should create five lane matchup rows:
- top
- jng
- mid
- bot
- sup

Each row compares the blue-side player against the red-side player in the same lane.

## Data It Consumes

### Source Table
- dbo.fact_lol_player_game

The script reads player rows where:
position IN ('top', 'jng', 'mid', 'bot', 'sup')

## Refresh Behavior

Then inserts the rebuilt lane matchup rows.

This is a full rebuild table.

## Diff Logic
For each comparison field, the script calculates:

blue value - red value

Examples:
- kill_diff = blue_kills - red_kills
- dk_diff = blue_dk - red_dk
- cs_diff_10_diff = blue_cs_diff_10 - red_cs_diff_10

Positive value means the blue-side player was ahead.
Negative value means the red-side player was ahead.

## Output Validation
The script prints:
- connected database
- player-game rows loaded
- blue rows
- red rows
- lane matchup rows created
- inserted lane matchup rows
- final SQL row count

Good signs:
- player-game rows > 0
- blue rows and red rows are close
- lane matchup rows should usually equal unique games * 5
- final SQL row count equals inserted rows

## SQL Health Checks

Check row counts:
SELECT
    league,
    season,
    COUNT(*) AS lane_matchup_rows,
    COUNT(DISTINCT game_id) AS unique_games,
    MIN(game_date) AS first_game_date,
    MAX(game_date) AS last_game_date
FROM dbo.fact_lol_lane_matchup
GROUP BY league, season
ORDER BY season DESC, league;

Check expected five lanes per game:
SELECT
    game_id,
    COUNT(*) AS lane_rows
FROM dbo.fact_lol_lane_matchup
GROUP BY game_id
HAVING COUNT(*) <> 5
ORDER BY game_id;

Check latest lane matchups:
SELECT TOP 50
    game_date,
    league,
    game_id,
    position,
    blue_team,
    blue_player,
    red_team,
    red_player,
    dk_diff,
    gold_diff_10_diff,
    cs_diff_10_diff,
    dpm_diff
FROM dbo.fact_lol_lane_matchup
ORDER BY game_date DESC, game_id, position;

## Important Risk Areas

### Risk 1: Full truncate and rebuild
The table is fully truncated before insert. If the insert fails, the target table can be left empty until rerun.

### Risk 2: Depends completely on fact_lol_player_game
If player-game data is stale or missing, lane matchup data will also be stale or missing.

### Risk 3: Requires clean blue/red side values
The script expects side values to normalize to:
- blue
- red

Bad or missing side data will reduce matchup rows.

### Risk 4: Requires one blue and one red player per position
If a game is missing a player row for a position, that lane matchup will not be created.

### Risk 5: Diff values are blue-minus-red
This is important when interpreting the data. Positive does not mean "winner"; it means blue side outperformed red side for that field.

## Recommended Future Enhancements
- Add a game/position uniqueness constraint to prevent accidental duplicates.
- Add a validation warning when lane rows per game are not 5.
- Add red-minus-blue alternate fields only if needed for easier interpretation.
- Add a derived winning-laner flag by position.
- Add lane matchup rating outputs for downstream model use.
