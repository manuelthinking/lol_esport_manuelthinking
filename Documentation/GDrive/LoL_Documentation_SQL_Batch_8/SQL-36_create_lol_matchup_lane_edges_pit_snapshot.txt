# SQL-36_create_lol_matchup_lane_edges_pit_snapshot

## Source SQL File
36_create_lol_matchup_lane_edges_pit_snapshot.sql

## Purpose
Creates a physical snapshot table for the PIT matchup lane edges view.

In plain English:
This file creates an empty table using the structure of dbo.vw_lol_matchup_lane_edges_pit_v1. The snapshot table is used so downstream PIT backtest refresh logic can read lane-edge rows from a stable materialized table instead of recalculating the full PIT lane-edge view every time.

## SQL Object Created
Creates:

dbo.lol_matchup_lane_edges_pit_snapshot

This is a physical table.

## Data It Consumes

### Source View
- dbo.vw_lol_matchup_lane_edges_pit_v1

## Data It Creates / Updates
Creates the table only if it does not already exist.

It uses:

SELECT TOP 0 *
INTO dbo.lol_matchup_lane_edges_pit_snapshot
FROM dbo.vw_lol_matchup_lane_edges_pit_v1;

This creates the table structure only and inserts zero rows.

## Grain
The intended grain matches dbo.vw_lol_matchup_lane_edges_pit_v1.

Based on downstream usage, expected grain is:

target_series_id + team + opponent + lane

One normal target series should usually produce:
- 10 rows
- 5 lanes from Team A perspective
- 5 lanes from Team B perspective

## Refresh Behavior
This file does not refresh or insert data.

Refreshing is handled by:

37_refresh_lol_matchup_lane_edges_pit_snapshot.sql

Indirect downstream:

## Important Risk Areas

### Risk 1: Depends on missing upstream PIT lane-edge view
This table cannot be created unless dbo.vw_lol_matchup_lane_edges_pit_v1 already exists.

### Risk 2: Creates empty table only
After this file runs, the table has no rows until file 37 is run.

### Risk 3: SELECT * table creation
The table structure depends entirely on the current shape of dbo.vw_lol_matchup_lane_edges_pit_v1. If that view changes later, the snapshot table will not automatically update.

### Risk 4: No indexes created here
This file does not create indexes. File 38 may be missing and should be checked.
